All High findings were independently re-verified against the working tree before inclusion. Severity: **High** = operator cannot complete or safely perform a real task; **Medium** = workaround exists but costs time or invites mistakes; **Low** = polish/consistency.

## 1. `/admin` — login / landing

- **[Medium] [action feedback] A-1 — Rate-limit lockout is reported as "Incorrect password"** — evidence: `components/admin/PasswordGate.tsx:44-50` handles only `res.ok` and 503; the 429 throttle response (`app/api/admin/verify-password/route.ts:49-55`, message "Too many attempts. Try again later.") falls into the generic branch and renders "Incorrect password. Please try again.". Operator impact: a throttled operator typing the *correct* password is told it is wrong, inviting futile retries or an unnecessary reset. Minimal fix: add a `res.status === 429` branch that surfaces the server message.
- **[Low] [action feedback] A-2 — Raw machine token `admin_auth_unavailable` shown on 503** — evidence: `PasswordGate.tsx:46-47` renders `data.error` verbatim; the server sends the literal `admin_auth_unavailable` at `app/api/admin/verify-password/route.ts:47,75`. Operator impact: during a DB outage the login screen shows an undecipherable snake_case token. Minimal fix: map known error codes to human sentences client-side.
- **[Low] [consistency] A-3 — Password input lacks `autoComplete="current-password"`; error not announced** — evidence: `PasswordGate.tsx:79-100` (no `autoComplete`, error `<p>` not linked via `role="alert"`/`aria-describedby`). Operator impact: password managers may not offer the admin password; screen readers don't announce failures. Minimal fix: add `autoComplete` and `role="alert"`.

## 3. `/admin/bookings` — the booking operations console

### High
